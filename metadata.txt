about=🧭 FilterMate explores, filters and exports vector, raster and LiDAR point cloud layers from one panel.

    Pick a layer, select what matters on it, and FilterMate filters the other layers of the project by their relation to that selection: buildings near main roads, parcels on steep slopes, LiDAR points beneath rooftops, a DTM clipped around a church. Filters stay on the existing project layers, keep their styles, can be undone, saved as favorites, exported and replayed from Processing.

    🧭 EXPLORING selects on the current layer, whatever its kind:
    - 🗺️ vector: one feature, several, or an expression;
    - 🏔️ raster: band, pixel value picked on the map, value range on a live histogram, classes, raster calculator expression;
    - ☁️ point cloud (LAS, LAZ, COPC, EPT, VPC): ASPRS / LiDAR HD classes, Z, intensity and return ranges, attribute conditions, height above a DTM.

    🔍 FILTERING relates that selection to layers of any kind (9 source / target combinations) with geometric predicates, a buffer, AND / OR with existing filters and a minimum coverage for polygons. Filtered rasters and point clouds keep their id, style and place in the layer tree, and the project is always saved with the original sources.

    📦 EXPORTING writes the filtered layers: vector formats, GeoPackage with an embedded QGIS project, GeoTIFF / COG, LAZ / LAS / COPC.

    🤖 AGENT (experimental) does it from a sentence: "buildings above 1200 m in the selected commune". It reads the project, filters, selects, zooms, styles and labels layers, edits features (in the edit buffer, saved by you), makes print layouts, adds open data, runs Processing algorithms of QGIS, draws objects with SAM and exports, with Claude, Mistral, OpenAI, a compatible server, a local Ollama model, or a few free requests a month to try it. Filters apply at once and each step can be undone; exports and added or removed layers are confirmed. A built-in MCP server, off by default, lets Claude Code or another client on your computer use the same tools.

    🧩 Objects drawn by SAM (experimental): on an orthophoto, a click or a box and the SAM 2.1 model draws the object, locally on your CPU; similar objects are proposed, to keep or reject. The objects filter other layers, become a polygon layer, or are drawn from a layer of points or footprints in Processing.

    ✨ Also: PostgreSQL / PostGIS, Spatialite, GeoPackage and OGR backends with spatial indexes; undo / redo; favorites shared through git repositories; ten Processing algorithms and four models, qgis_process, Python and REST APIs, MCP servers; light and dark themes; 34 languages. QGIS 3.22 to 4.x, Qt5 and Qt6.

    🔧 Optional: psycopg2 for PostgreSQL, PDAL 2.4+ for the height above a DTM and COPC writing, onnxruntime and the SAM model (62 MB) for the objects, installed after a confirmation.

    📖 User guide: https://imagodata.github.io/filter_mate/guide.html
    💡 Sixteen use cases in English and French: https://imagodata.github.io/filter_mate/stories.html

changelog=v5.1.0 (2026-11-10): First version published since 5.0.2. Two experimental sections. AGENT - a chat in the dock that filters, selects, zooms, adds open data and exports from a sentence, with Claude, Mistral, OpenAI, a compatible server or a local Ollama model and your own API key (kept in the QGIS authentication database), or a few free requests a month through a relay of FilterMate to Claude Haiku 5.5. The map, the layer tree and what changed go with each request, and the agent reads statistics, samples of features and what lies at a point instead of guessing, runs Processing algorithms of QGIS that make layers (native and qgis providers only, each layer made removed when the turn is undone), styles and labels a layer, edits features in the edit buffer without ever saving them, and reads, draws or finds similar objects with SAM. Filters apply at once and each step of a request can be undone or redone; exports and added or removed layers are confirmed; a filter written by the model is one plain WHERE clause checked against a list. Optional sources, all off until ticked: open data portals, WFS services, Sentinel-2 scenes, remote MCP connectors. An MCP server built into the plugin, off by default, lets Claude Code or another client on this computer use the same tools. Objects drawn by SAM - in the raster pipette, a click or a box and the SAM 2.1 model draws the object locally on the CPU (onnxruntime and the 62 MB model installed after a confirmation); similar objects are proposals to keep or reject; To layer turns them into a polygon layer; a new Processing algorithm draws one object per point or polygon of a layer, and Processing, the REST API and MCP accept objects as a raster selection. Dock - two stacks of sections (AGENT and EXPLORING above, FILTERING, EXPORTING and CONFIGURATION below), favorites, float and close in the title bar. The REST API and the stdio MCP server accept only plain WHERE clauses in apply_filter and preview_filter (breaking). Translations of AGENT, the favorites menu and the Processing algorithms restored in the 34 languages.

Small scaled screens - a 1080p laptop scaled to 150 percent gets the compact profile instead of a dock too tall for its area, and the EXPLORING tools scroll instead of overlapping. The UI_PROFILE setting now works, at once and at startup. Several features that failed only in QGIS work: custom expressions in the exploring features, layers saved without their linking option, choosing where to save a single exported layer, the expression debounce setting. A custom expression matching nothing no longer empties the single selection list. Scrolling the dock no longer changes a list or a number by accident: they answer the wheel once clicked. Search bar in the Configuration tab. One order for the EXPLORING tools on every layer kind.
