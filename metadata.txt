about=🧭 FilterMate explores, filters and exports vector, raster and LiDAR point cloud layers from one panel.

    Pick a layer, select what matters on it, and FilterMate filters the other layers of the project by their relation to that selection: buildings near main roads, parcels on steep slopes, LiDAR points beneath rooftops, a DTM clipped around a church. Filters stay on the existing project layers, keep their styles, can be undone, saved as favorites, exported and replayed from Processing.

    🧭 EXPLORING selects on the current layer, whatever its kind:
    - 🗺️ vector: one feature, several, or an expression;
    - 🏔️ raster: band, pixel value picked on the map, value range on a live histogram, classes, raster calculator expression;
    - ☁️ point cloud (LAS, LAZ, COPC, EPT, VPC): ASPRS / LiDAR HD classes, Z, intensity and return ranges, attribute conditions, height above a DTM.

    🔍 FILTERING relates that selection to layers of any kind (9 source / target combinations) with geometric predicates, a buffer, AND / OR with existing filters and a minimum coverage for polygons. Web maps (WMS, WMTS, tile basemaps) can be filtered too: captured over the area, then cut like a local raster. Filtered rasters and point clouds keep their id, style and place in the layer tree, and the project is always saved with the original sources.

    📦 EXPORTING writes the filtered layers: vector formats, GeoPackage with an embedded QGIS project, GeoTIFF / COG, LAZ / LAS / COPC.

    🤖 AGENT mode (experimental) is a chat in the panel that drives FilterMate and QGIS from a sentence: "buildings above 1200 m in the selected commune". How it works:
    1. You choose the model: Claude, Mistral, OpenAI or a compatible server with your own API key, kept in the authentication database of QGIS, or a local Ollama model, with which your requests stay on your computer. No account and no telemetry: FilterMate holds no key and has no server of its own. The settings guide you (a link to create a key, a Test button, the download of an Ollama model).
    2. You write what you want in the AGENT section. With each request go your message, the extent of the map and the layer tree (names, types, fields, CRS); field values and an image of the map go only if you allow them, and the chat asks for your consent the first time you use a provider.
    3. The agent works step by step with its tools, each step shown in the thread: it reads before it acts, tries a filter before applying it, and asks with choices to click when a choice is yours.
    4. You stay in control: filters apply at once and each step, or the whole request, can be undone; exports, deletions and added or removed layers are confirmed; you choose how far it goes alone (four levels of autonomy, a rule per tool, layers it must never change).
    What it does:
    - 🔎 reads the project: layers, fields and their values, statistics, samples of features, what lies at a point, the map as you see it;
    - 🔍 filters: by attributes, across layers (geometric predicates, buffer), by a geometry, point clouds, favorites; it tries a filter before applying it, and undoes or redoes it;
    - 🎯 selects features, zooms, shows and hides layers, keeps bookmarks and map themes;
    - 🎨 styles and labels layers (rules, color ramps, labels by expression or along lines), groups, renames, duplicates and removes layers, adds fields and joins tables;
    - ✏️ adds, updates and deletes features in the edit buffer, saved by you;
    - 🌍 brings data in, each from a source you tick: files, WFS, WMS and WMTS services, the tables of a PostgreSQL connection, web basemaps, open data portals, Sentinel-2 scenes, the elevation of an area and its contour lines, OpenStreetMap features, the population, the natural risks of France; it finds a place by its name;
    - ⚙️ runs the Processing algorithms of QGIS; draws objects with SAM and finds similar ones;
    - 🖨️ makes and exports print layouts, sets the CRS of the project, exports the filtered layers;
    - 🧩 asks with choices to click when a choice is yours, follows your own skills, uses the MCP servers you connect, and keeps a request as a recipe that runs again without any model.
    An expert mode, off by default, lets it run Python code in QGIS, shown and confirmed at each run. A built-in MCP server, off by default, lets Claude Code or another client on your computer use the same tools. With no model at all, Set up FilterMate asks the main settings with a few choices, and How FilterMate works tells the panel section by section. What is sent, to whom and when: https://github.com/imagodata/filter_mate/blob/main/docs/AI_AND_DATA.md

    🧩 Objects drawn by SAM (experimental): on an orthophoto, a click or a box and the SAM 2.1 model draws the object, locally on your CPU; similar objects are proposed, to keep or reject. The objects filter other layers, become a polygon layer, or are drawn from a layer of points or footprints in Processing.

    ✨ Also: PostgreSQL / PostGIS, Spatialite, GeoPackage and OGR backends with spatial indexes; the sections of the panel listed in a rail, and shown as panels of QGIS when you ask, alone or grouped; undo / redo and the history of the project, to go back to before any step; Compare, the map before and after a filter on each side of a line; favorites shared through git repositories; ten Processing algorithms and four models, qgis_process, Python and REST APIs, MCP servers; light and dark themes; 34 languages. QGIS 3.22 to 4.x, Qt5 and Qt6.

    🔧 Optional: psycopg2 for PostgreSQL, PDAL 2.4+ for the height above a DTM and COPC writing, onnxruntime and the SAM model (62 MB) for the objects, installed after a confirmation.

    📖 User guide: https://imagodata.github.io/filter_mate/guide.html
    💡 Sixteen use cases in English and French: https://imagodata.github.io/filter_mate/stories.html
